## Qué se fusionó

Reemplaza la lógica mock de `AuthProvider`/`login()` de la spec 03 por
autenticación real contra Supabase (email + password), persistiendo la sesión
con `AsyncStorage` según la recomendación oficial del SDK de Supabase para
React Native. La UI (formulario, rutas, guard del Dashboard, botón de logout)
no cambia, solo lo que hay detrás:

- `src/lib/supabase.ts` (nuevo): cliente de Supabase con
  `storage: AsyncStorage`, `autoRefreshToken: true`, `persistSession: true`,
  `detectSessionInUrl: false`.
- `src/contexts/auth-context.tsx` (reescrito): `AuthProvider` usa
  `supabase.auth.getSession()`/`onAuthStateChange`/`signInWithPassword`/
  `signOut`; `AuthUser` pasa a `{ id, email, displayName, avatarInitials }`.
  Elimina por completo `expo-secure-store` y el token simulado de la spec 03
  (incluida la excepción `Platform.OS !== 'web'` que dejaba la sesión sin
  persistir en esa plataforma — ya no aplica, `AsyncStorage` funciona en todas
  las plataformas).
- `src/app/_layout.tsx` (actualizado): agrega
  `import 'react-native-url-polyfill/auto';` como primera línea del entry
  point (requerido por el SDK de Supabase en React Native).
- `src/components/dashboard/dashboard-header.tsx` (actualizado): usa
  `displayName` en vez del `name` mock.
- `app.json`: quita el plugin `expo-secure-store`.
- `package.json`/`package-lock.json`: agrega `@supabase/supabase-js`,
  `@react-native-async-storage/async-storage`, `react-native-url-polyfill`;
  quita `expo-secure-store`.
- `specs/04-supabase-auth.md` (actualizado): Estado → Implemented, checklist
  de criterios de aceptación marcada.
- `.env.local` (no versionado, fuera de este commit): renombrado
  `NEXT_PUBLIC_SUPABASE_URL`/`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` →
  `EXPO_PUBLIC_SUPABASE_URL`/`EXPO_PUBLIC_SUPABASE_ANON_KEY` (mismos valores).
  `SUPABASE_SERVICE_ROLE_KEY` no se toca ni se referencia en ningún código de
  la app (verificado con `grep -r SUPABASE_SERVICE_ROLE_KEY src/`).
