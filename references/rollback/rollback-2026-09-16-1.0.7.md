## Qué se fusionó

Normaliza el `display_name` de todos los usuarios de Supabase a partir de la parte local de su
email, unifica la `SessionHeader` en todas las pantallas logadas incluida Home, y hace que el tab
seleccionado tras el login sea Dashboard. Reabre las decisiones nº4 y nº9 de la spec `06` (Home como
primer tab, Home logada sin cabecera): ninguna de las dos sobrevive a los requisitos de esta spec.

- `scripts/backfill-display-name.sql` (nuevo): `UPDATE` con merge sobre `raw_user_meta_data` que
  escribe `display_name` a partir de la parte local del email (separadores no alfanuméricos →
  espacio, cada palabra capitalizada), sin filtrar por dominio.
- `scripts/backfill-display-name.mjs` (nuevo): equivalente ejecutable vía Admin API
  (`listUsers` + `updateUserById`), usado porque el MCP de Supabase no conectaba (`HTTP 400`).
  Ejecutado sobre 19 usuarios el 2026-09-16; verificado idempotente y que `email_verified`
  sobrevive al merge.
- `src/contexts/auth-context.tsx`: `mapSupabaseUser` resuelve `displayName` como
  `display_name ?? full_name ?? name ?? email` (antes: `full_name ?? name ?? email`).
- `src/app/(app)/_layout.tsx`: `SessionHeader` se renderiza siempre — se elimina `usePathname()` y
  el condicional `showSessionHeader` que la excluía en `/home`; se elimina
  `export const unstable_settings = { anchor: 'dashboard' }`, que no controla el tab inicial de
  `NativeTabs`.
- `src/components/app-tabs.tsx`, `app-tabs.web.tsx`: triggers reordenados a
  `[Dashboard][Home][Explore]` (antes `[Home][Dashboard][Explore]`) — el primer trigger es el tab
  inicial.
- `src/components/home-screen.tsx`: el CTA ("Iniciar sesión"/"Cerrar sesión") solo se renderiza sin
  sesión; con sesión el logout vive únicamente en `SessionHeader`. El `SafeAreaView` excluye el
  borde `top` con sesión (`edges={safeAreaEdges}`) para no duplicar el inset que el layout de
  `(app)` ya consume. `logout` sale de la desestructuración de `useAuth()`.
- `specs/07-display-name-cabecera-y-tab-inicial.md`: Estado → Implemented, criterios de aceptación
  marcados.

**No se tocó** la lógica de guards/`Stack.Protected` de la spec `06`, `(public)`, `login.tsx`, el
spinner de `isLoading`, el contenido de Dashboard/Explore más allá de heredar la cabecera que ya
tenían, ni `avatarInitials`.

## Cómo revertir (opción recomendada — no destructiva)

```bash
git revert 5f97b372064345789c472b0650e72452d23f8f84
```

> El merge fue fast-forward, así que no es un commit de merge real (no necesita `-m 1`).

Esto crea un commit nuevo que deshace los cambios de código de esta spec sin reescribir historia,
seguro para usar aunque `master` ya haya sido pusheado.

**Importante:** revertir este commit **no revierte el backfill de Supabase** — `git revert` solo
deshace archivos del repo, y `scripts/backfill-display-name.mjs`/`.sql` son artefactos, no
migraciones automáticas. Tras el revert:

- `mapSupabaseUser` vuelve a `full_name ?? name ?? email`, así que `display_name` deja de leerse en
  la app (aunque siga almacenado en Supabase).
- `SessionHeader` vuelve a excluirse en `/home`, la tab bar vuelve a `[Home][Dashboard][Explore]`,
  `unstable_settings.anchor` reaparece, y Home logada recupera su CTA "Cerrar sesión".
- Si además se quiere deshacer el dato en Supabase, hay que restaurar `raw_user_meta_data` a mano
  (no hay backup automático del valor previo de `display_name`, que en los 19 usuarios no existía).
